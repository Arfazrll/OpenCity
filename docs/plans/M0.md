## Definition of Done (from 2.18 + 1.9)

The milestone is finished only when **all** of these are observed true, not assumed:

- [ ] Runs on the dev laptop (release build launches, no panic).
- [ ] The whole 16 km terrain is navigable with **no visible LOD cracks**.
- [ ] Roads **and** buildings can be placed, with working undo.
- [ ] Day-night cycle works.
- [ ] Graphics presets switch **at runtime**.
- [ ] Specs and FPS recorded (`docs/reports/M0-environment.md` + FPS table in `docs/reports/M0.md`).
- [ ] All quality gates pass (`verify` skill, 3.8).
- [ ] 6 screenshots captured: dawn, noon, dusk, night, 5 km altitude, street level.
- [ ] `docs/reports/M0.md` written in Bahasa Indonesia with copy-paste run commands.

## Step 3 — `world-model`: coordinates and chunk math (2.4)

Pure logic, no Bevy render deps, fully unit-testable. Doing this before rendering means the terrain
and camera code have one authoritative source for "where things are".

1. `Meters`, `Seconds`, `GameTime` newtypes (3.9 strong types).
2. Plot constants: 16 km extent, 4 m heightfield resolution (4000 × 4000), `u16` encoding with 0.02 m
   steps over −100 m … +1210 m, 256 m render chunks (64 × 64), 32 m sim cells (500 × 500).
3. Conversions: world ↔ heightfield sample ↔ chunk index ↔ sim cell, with clamping at plot edges.
4. Generational IDs (`u32` index + `u32` generation) with a reusable `IdArena`.
5. Quadtree chunk addressing for LOD levels.

**Acceptance**
- Unit tests: round-trip every conversion; verify the `u16` height encoding is exact at 0.02 m steps
  and that −100 m and +1210 m are representable.
- Property test (`proptest`): any world position inside the plot maps to an in-range chunk and cell.
- Height encode/decode error ≤ 0.01 m across the full range.

**Commit**: `feat(world-model): add coordinates, chunk math and generational ids`

- Vsync toggle visibly changes the frame rate.
- The printed adapter line is recorded in the M0 report.

**Commit**: `feat(game): add app shell with fps overlay, presets and screenshot capture`

## Step 5 — Terrain generation (2.19 step 5, 2.8.1)

1. `procgen`: seeded fBm + domain-warped noise; ridged noise for hills; large-scale mask for
   coastlines. Deterministic from `(world_seed, system_id)` ChaCha streams (2.5.2).
2. Three presets: **Flat**, **Hills**, **Coastal** (+ sea level). River carving is M1 — M0 only needs
   the three presets to look distinct.
3. Output: `u16` heightfield (4000 × 4000 ≈ 32 MB), plus a basic material mask by slope and height.
4. Generate in parallel on `rayon`.

**Acceptance**
- Three presets produce visibly different terrain from the same seed.
- Same seed → byte-identical heightfield across runs (snapshot test with `insta` on a hash).
- Generation time measured and reported. Budget is "under 30 s on recommended hardware" (2.8.1);
  this machine is below that tier, so **measure and report honestly** rather than claim the budget.
- Heightfield memory ≈ 32 MB as designed, not more.

**Commit**: `feat(procgen): add seeded terrain generation with flat, hills and coastal presets`

## Step 6 — Terrain rendering with chunk LOD (2.19 step 5, 2.6.2) ⚠️ hardest step

1. `render`: 256 m chunks, quadtree LOD, **crack-free** seams (CDLOD-style vertex morphing; skirts
   as the fallback if morphing fights Bevy 0.20's mesh API).
2. Distance-based streaming with load/unload radii and LOD bias per preset (2.6.7).
3. Material splatting by slope and height using placeholder procedural colours — **no downloaded
   textures in M0**, so `assets/LICENSES.md` stays empty and the licensing gate stays trivially
   green.
4. Distance fog to hide the streaming horizon.

**Acceptance**
- Fly the full 16 km at several altitudes: **no visible cracks or popping seams** (this is in the
  DoD, verified by eye on the 6 screenshots plus a free-fly pass).
- Chunk count actually loaded stays bounded; memory does not grow while flying in circles
  (10-minute fly-around, watch RSS).
- Frame time at 5 km altitude recorded per preset.

**Risks**
- This is where the iGPU will hurt most. If Low cannot hold 30 fps at 5 km, apply the blueprint's own
  escape hatch: Low preset caps the active city to the central **8 km** (2.6.8) and uses 75% render
  scale.
- Bevy 0.20 changed renderer APIs; **check Context7 for `v0.20.1`** before writing mesh/material
  code, never from memory.

**Commit**: `feat(render): add quadtree terrain chunks with crack-free lod and streaming`

## Step 9 — Road tool v0 (2.19 step 8)

1. Click to place **straight** and **curved (cubic Bezier)** segments.

3. Extruded road mesh draped onto the terrain heightfield.
4. Demolish.
5. **Commands with inverses** (2.1) — this is the undo/redo foundation, and getting it right here is

**Acceptance**
- Straight and curved segments both place and render, draped on slopes without floating or sinking.
- Grid snap visibly snaps; toggling it off allows free placement.
- Undo/redo (Ctrl+Z / Ctrl+Y) restores exact prior state — verified by comparing a state hash.
- Demolish removes geometry and is itself undoable.

**Commit**: `feat(game): add road tool v0 with straight and bezier segments and grid snap`

## Risks for this milestone

| Risk | Severity | Mitigation |
| --- | --- | --- |
| **Step 6 (terrain LOD) is the whole milestone's difficulty.** Crack-free quadtree LOD on a weak iGPU across 16 km is the one genuinely hard piece. | **High** | Do it after `world-model` is tested so chunk math is not in doubt. Skirts as the fallback if CDLOD morphing fights the 0.20 mesh API. Fall back to the Low preset's 8 km cap, which the blueprint already sanctions. |
| **Bevy 0.20 API churn** — training memory is unreliable for 0.20's renderer and WESL shaders. | **High** | Query Context7 for `/bevyengine/bevy` at `v0.20.1` before each unfamiliar API. Never write renderer code from memory. |
| **iGPU cannot hold 30 fps at Low** even with escape hatches. | Medium | If it genuinely cannot, that is a 3.11 decision gate ("a performance budget that cannot be met without a design change") → stop, measure, write an ADR draft, ask the owner. Do not quietly cut scope. |
| **Long Windows compile times** with Bevy on a 15 W CPU. | Medium | `dynamic_linking` for dev builds, `opt-level = 3` for deps only, small crates, incremental. Expect the first full build to be slow; measure it once and report it. |
| **`C:` is down to 22.1 GB free** — the bootstrap cost ~7.7 GB (VS Build Tools + SDK + cargo registry), and `%USERPROFILE%\.cargo` will keep growing as Bevy's dependency tree lands there. | **High** | All `target/` output stays on `D:`. Check free space before each milestone. If `C:` drops under ~10 GB, move `CARGO_HOME` to `D:\app\Others\OpenCity\.cargo-home` and re-fetch. |
| **60 Hz panel + no 1440p** makes two blueprint checks unverifiable as written. | Low | Vsync off for all measurements; report 1440p as not testable rather than inventing numbers. |
| Scope creep into M1 (water, erosion, terraforming, real radial menu). | Low | Those are M1/M2 rows in 2.18. M0 stops at the list in 2.19. |
